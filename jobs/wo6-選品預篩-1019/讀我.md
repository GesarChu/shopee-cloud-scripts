# 選品預篩（工單 #6）讀我：規則檔每一條的意思和來源

程式：`tools/s-prefilter.py`。門檻、字典、排序**全部**從 `規則.json` 讀，程式裡沒有寫死。之後要調只改 json，不用改程式。
- 底線開頭的鍵（`_說明`、`_min_monthly_sales`…）是說明，程式不讀。
- 規則檔少了下面任何一個鍵，或值看不懂（例：`done_policy` 寫了 exclude／demote／mark 以外的字）⇒ exit 2，不產出候選表。

```
python tools/s-prefilter.py --offers 第1頁.csv 第2頁.csv … --done 做過清單.txt \
    --rules jobs/wo6-選品預篩-1019/規則.json --columns jobs/wo6-選品預篩-1019/欄位對照.json \
    --today 2026-10-19 --out 輸出資料夾
```

## 規則.json

| 鍵 | 意思（程式怎麼用） | 來源 |
|---|---|---|
| `stage` | 目前第幾階段。排除理由寫「第 stage+1 階段品類：…」 | 查理王四階段；王 10/19 07:5x 經 44；43 候選-20261019 開頭 |
| `categories` | 本階段可做的品類字典。品名（拿掉促銷字、容量後）或 CSV 的品類欄**含**某個字，就算那一類；也可以在 CSV 品類欄直接寫類名（`熱賣商品` 的字典是空的，只能這樣進來） | Kai 起頭、43 確認並補字（10/19 10:5x） |
| `later_stage_categories` | 後面階段的品類字典。只對到這邊 ⇒ 排除，理由「第 3 階段品類：<類>」。兩邊都對到 ⇒ 標「品類衝突（待人判）」、⛔ 排除。都對不到 ⇒ 標「未分類（待人判）」、留在候選 | 同上；`_categories` |
| `min_monthly_sales` | 月銷下限。取「+」前面的數字，**嚴格小於**才排除（「1,000+」＝1000 留著，並標「月銷剛好 1000 留著」） | 43 10/19 07:0x；10:5x 核成嚴格小於 |
| `trap_commission_min` | 沒有月銷（空白或 0）時：列表分潤 ≥ 這個數 ⇒ 理由「沒有月銷＋列表分潤 X% ≥ 15（小店衝曝光）」；低於 ⇒ 理由「沒有月銷」。兩種都排除 | 43 10/19 07:4x（20.5%、18.5%、15.5% 都沒月銷） |
| `same_product_min_stores` | 同款家數下限。家數＝max（前台同款家數欄, CSV 同組沒被排除的不同賣場數）。前台欄有填、而且家數 < 這個數 ⇒ 排除。前台欄空白：CSV 自己就 ≥ 這個數 ⇒ 顯示「N（CSV）」；不到 ⇒「待數（CSV k 家有效）」、不排除，下一步加「前台數家數」 | 候選-20261011-晚上；Fable 42 10/11 19:5x |
| `same_flavor_max_reject` | 同口味家數 ≤ 這個數 ⇒ 排除，理由「同口味 ≤2 家（前台 N）」。家數算法同上，也只在前台欄有填時才擋 | Fable 42 10/11 19:5x |
| `done_policy` | 對做過清單。`same_brand_same_series`：同品牌、系列也對到（清單系列空白＝整個品牌）；`same_brand_other_series`：同品牌、系列不同。值：`exclude`＝排除、`demote`＝留著但整組排到最後、標「同品牌不同系列（降級，排最後）」、`mark`＝只標記 | 王經 44「優先跟現有品牌、系列都不同」；43 確認 |
| `require_bonus` | `false`：分潤加碼欄不是「是」只標「不是分潤加碼」（空白標「分潤加碼待查」）；`true`：排除 | 43 確認 |
| `offer_end_policy` | `exclude_member`：加碼到期日早於 --today ⇒ 只排除那一列，理由「推廣已到期（日期 早於 今天）」，同組其他家照留，組上標「列 N 推廣已到期，只剩列 …」；`mark`：只標記。空白 ⇒ 標「到期日待查」；讀不懂 ⇒ 標「到期日讀不到」 | 候選-20261011-晚上；事實表 #110 |
| `sort` | 排序鍵，依序比。目前 `monthly_sales desc`（月銷下限）、`per_order desc`（每單約 $）。另外可用 `price`、`commission_rate`；方向 `asc`／`desc`。讀不到、算不出來的排在同層最後；降級的整批排最後 | 第 2 階段流量優先、分潤次要 |
| `list_rate_note` | 說明用（程式不讀數字）：列表分潤率 ≠ 短影音 ⇒ 每單約 $ 用列表算的標「估」，下一步一律寫「開詳情看短影音那列」 | 43 10/11、10/19 06:5x |
| `promo_words` | 分組前從品名拿掉的促銷字（括號裡的也拿掉；括號拿空了連括號一起拿掉） | 樣本列 3「【免運現貨】」 |
| `flavor_words` | 口味字典。口味不同＝不同組。品名裡**單獨成詞**的口味字才算口味；沒有單獨成詞的，才在詞裡找「不是品類字」的口味字。所以「脆烤海苔」的「海苔」算品名主體，「洗碗精檸檬」的「檸檬」算口味 | 43 確認；`_flavor_words` |
| `capacity_pattern` | 容量、入數的正規式，分組前拿掉（500ml、110抽x12包、x3入…） | Fable 42 10/11：容量、入數不同＝同款 |

## 欄位對照.json
- 每個標準欄位可以有好幾個別名，比對時去頭尾空白、英文不分大小寫。
- CSV 有一個欄名對不到 ⇒ exit 2，列出那些欄名（⛔ 猜、⛔ 略過）。拿到新的後台匯出，只在這裡加別名。
- 兩個欄名對到同一個標準欄位 ⇒ exit 2。
- 英文介面的 `sold` 對到月銷（`monthly_sales`），不是總銷量。

## 做過清單
- 一行一筆「品牌｜系列」（半形 `|` 也可以），`#` 開頭是註解。系列空白＝整個品牌都算做過。
- 系列比對：清單系列是品名「品牌之後那段」的一部分就算同系列（「豆漿」對「無加糖豆漿」）。
- 正式版由本機從 `素材/商品卡/*/card.json` 產生，⛔ 進儲存庫。

## 數字怎麼讀
| 欄 | 讀得懂 | 讀不懂 |
|---|---|---|
| 月銷、已售 | 3萬+、1.2萬、6,000+、50萬+ sold、1千（記下有沒有「+」） | 標「讀不到（原字）」，⛔ 當 0。月銷讀不到不排除，標「月銷讀不到」、排在同層最後 |
| 價格 | $1,299、NT$59、59元 | 「洽詢」、價格區間（$59 - $99）⇒ 讀不到，每單約 $ 算不出來 |
| 分潤率 | 10.5%（一定要有 %） | 沒有 % 的數字分不出是 10.5% 還是 0.105 ⇒ 讀不到 |
| 前台同款家數 | 6、6家 | 讀不到 ⇒ 當成空白（待數）並標出來 |
| 到期日 | 2026/12/31、2026-12-31、2026.1.5 | 標「到期日讀不到」 |

- 每單約 $：價格 ×（短影音＋獎勵）%（標「實」），沒有短影音用列表分潤率（標「估」）。
- 用 Decimal 算，ROUND_HALF_UP 到小數 2 位（10.395 → 10.40）。
- 一組取各家的最大值，其他家也列在同一格。

## 同款分組
1. 品名先 NFKC（全形英數變半形），拿掉 promo_words、capacity_pattern、拿空了的括號、括號符號。
2. **品牌**＝第一個詞。品名沒有空格的（例：「【免運現貨】晴空洗碗精檸檬500ml x3入」），拿其他列或做過清單出現過的品牌當前綴比；都對不到 ⇒ 標「品牌待人判」。
3. **口味**照上面 `flavor_words` 的規則找；**系列**＝品牌之後、拿掉口味的部分。
4. (品牌, 系列, 口味) 完全一樣＝同組。
5. **分組待人判**（程式不併，寫進 `分組.json` 和 `候選.md`）同時符合以下條件的配對：
   - 品牌一樣、組不一樣；
   - 口味沒有「兩邊都有而且不同」；
   - 兩邊系列含同一個品類字，或一邊的系列包含另一邊。
   - 例：「晴空 洗碗精 檸檬」跟「晴空 濃縮洗碗精 檸檬」。
6. 同一個 shop/item 在好幾份 CSV 都出現（同一頁存了兩次）⇒ 後面的排除，理由「重複」。

## 輸出
- `候選.md`、`候選.csv`（UTF-8 有 BOM，給 Excel）。
- `排除.csv`：每列＋全部理由代碼；備註寫同組誰照留。
- `分組.json`：每組有哪些列、每列拿掉了什麼字、比對字串；含 `分組待人判`。
- 畫面印摘要：讀幾列、幾組、候選幾組、各理由排除幾列、候選前幾名。
- exit 2（讀不了）時不產候選表，`--out` 裡舊的四個輸出檔會刪掉，免得拿到上次的結果。
