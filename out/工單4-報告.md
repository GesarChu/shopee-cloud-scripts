## 2. 各工具做法與門檻怎麼定的

門檻都寫成檔頭常數，旁邊註明理由。**以下都是依 README 的數字跟合成資料定的初值，樣本到了要再校準。**

### A. motion-gate（動態閃爍）
- 做法：每格灰階，d[t]＝相鄰兩格的平均絕對差。d 超過 `CUT_ABS=12` 的地方當轉場切開。每段（≥10 格）判三件事：
  - ①相鄰差平均 ÷ 段平均 > `OSC_RATIO=0.25`，或去趨勢後 2–8 格週期的自相關 > `AC_MIN=0.35` → FAIL；
  - ②靜止段（中位數 < `STATIC_MED=0.3`）出現週期性尖峰（≥3 次，75% 間隔一致）→ FAIL；
  - ③其餘 PASS。
- 合成自測的數字跟 README 寫的實測很像：
  - 舊片：d＝`1.58 1.80 0.96 2.03 1.02 …`，比值 0.69；靜止段每 5 格跳一次 → FAIL。
  - 新片：d 平平的約 0.65，相鄰差 0.007，比值 0.01 → PASS。
- **要注意**：README 給的舊片數字（`1.7 1.4 1.4 1.8 0.9 …`）算起來比值大約 0.24–0.3，正好壓在 0.25 線上。所以真樣本很可能是靠自相關（4–5 格週期）判 FAIL，不是靠比值。樣本到了要看實際數字再決定門檻。
- 加了一個工單沒寫的「擺幅門檻」`AMP_MIN=0.08`：新片第 2 段的自相關其實有 0.72（極小的規律雜訊），但擺幅（標準差÷平均）只有 0.008；沒有這道門檻，平滑的片也會被判 FAIL。舊片兩段的擺幅是 0.50 和 2.06。

### B. ghost-text-gate（label 框外的假字）
- label 框：`|後−前|` 三通道取最大差，> 25 灰階 → 閉運算補字縫 → 取最大連通塊（面積相近又相鄰的塊併進來）→ 膨脹 6px。
- 搜尋範圍：label 框往上 60%、左右各 25%，扣掉 label 框（再多扣 3%）；也可以用 `--product-box` 自己指定範圍。
- 找字：
  - 深字用黑帽、淺字用白帽，**分開做**。一開始合在一起做，深字之間的淺色字縫會被白帽當成筆畫，整列字黏成一塊實心長條被濾掉；合成自測抓到這個漏判才改的。
  - 留「字大小」的連通塊：字高為 label 框高的 1.8%–20%、寬高比 0.12–3.5、填滿率 0.12–0.85。
  - 高度相近、上下對齊、間距 ≤ 1.6 個字高的塊串成一列；≥3 個塊、而且邊緣方向熵 ≥ 0.55（擋單向條紋），才算一行字。
- 輸出標記圖：綠＝label 框、黃＝搜尋範圍、紅＝判定為字。

### C. review-sheet（人眼重驗圖）
- 每鏡一欄：
  - 上半是商品 1:1 特寫：商品框＝label 框往上 60%、下 25%、左右 25%，上下再各多 150px。
  - 下半是整格縮 50%，黃框標出特寫的範圍。
- 總寬超過 3800 就換行。超過 3 MB 先把 JPEG 品質從 90 往下降到 58，還不夠才把整格縮圖縮到 40%／33%；**商品特寫一律保持 1:1**。
- 某鏡沒有貼回前的圖就給 `-`，那一鏡用備用框，欄頭標紅字 `NO LABEL BOX`。

### D. composite-real（研究＋原型；三步都有）
1. **接觸陰影**：
   - 比較模型盒子底部左右兩側的地面亮度，判斷影子往哪邊；左右差 < 4% 就當光從正上方來。
   - 畫三層：貼地接觸線、底部扁橢圓軟陰影、壓扁斜拖的投影。
   - 深度依場景原有影子的深淺（夾在 0.25–0.65）。
2. **色調／銳利度**：
   - 色彩參考用「模型在場景光線下畫的那個盒子」（GrabCut 切出來）。Lab 往它靠：亮度 80%、色彩 60%、對比最多 ±40%。部分轉移是為了不把真品的字色洗掉。
   - 銳利度：找一個高斯 σ，讓真品的拉普拉斯能量接近場景盒子；**σ 上限 1.0px（字要清楚）**。
   - 最後補上場景的顆粒雜訊，邊緣羽化。模型盒子露在真品外面的部分用 inpaint 蓋掉，避免出現兩層輪廓。
3. **透視判斷**：GrabCut 切出模型盒子，跟真品去背輪廓比三件事：
   - 形狀 IoU < 0.80 → 不能貼；
   - 頂邊斜角差 > 10° → 不能貼；
   - **缺角在哪一組對角**：3/4 角的盒子，側面在右會缺左上＋右下，側面在左會缺右上＋左下。模型跟真品方向相反 → 不能貼。
   - 第三項是後來加的：只比 IoU 的話，3/4 角盒子的外輪廓接近左右對稱，鏡像後 IoU 0.90 對 0.92，分不出來。
- 用法：`--scene 場景.jpg --product 真品.png --box x,y,w,h --compare 對照.jpg --fake 現行貼法.jpg`。判「不能貼」時照樣輸出，對照圖下方標紅字。
- 已知弱點：
  - 銳利度用拉普拉斯能量配對，會受畫面內容影響。合成場景的模型盒子是素面的，目標被拉低，真品上的小字因此偏糊（σ 0.8）。建議下一步改成量邊緣寬度（10–90% 上升距離）換算 σ。
  - `--box` 目前要人給，沒有自動找模型盒子。

## 3. 誤判來源（預期）

這些是依做法推出來的，**還沒有真樣本可以證實**：

- **B 誤判成 FAIL**：
  - 真品標籤本身的小字落在 label 框外。例如模型原本就畫了幾乎一樣的小字，`後−前` 差異太小，那塊沒被算進 label 框。ax_shot2 的「請倒入瓶裝使用」就是這種風險，要看樣本。
  - 商品後面的招牌、海報、包裝紙上的字落在搜尋範圍內。
  - 規則排列的紋理（格紋桌布、百葉窗），只靠方向熵不一定擋得掉。
- **B 誤判成 PASS**：
  - 假字很小（< 6px）、很淡（筆畫對比 < 28），或筆畫連成一團（模型畫的糊字）。
  - 假字在 label 框正下方（目前不往下找）。
- **A**：
  - 編碼雜訊。H.264 的 B 格／P 格品質不同，會造成小週期，靠擺幅門檻擋。
  - 鏡頭裡有真的規律動作（例如閃爍的燈）會被當成閃爍。
  - 只量商品區（`--box`）比整張準：背景有動的東西會稀釋或干擾。
- **D**：
  - 地面是花紋桌布、或盒子貼著畫面邊緣時，左右亮度比不準，影子方向會判錯；可以用 `--shadow-dir` 指定。
  - 模型盒子跟背景顏色接近時 GrabCut 會切壞，透視判斷跟色彩參考都會跟著錯。

## 4. 本機流程該改的地方

1. **樣本／附件會被 `.gitignore` 吃掉，這次就是這樣**。commit 訊息寫「樣本 4.6 MB」，實際一個位元組都沒進去。建議二選一：
   - (a) 交接樣本一律 `git add -f`；
   - (b) `.gitignore` 加例外 `!jobs/**/fixtures/**`。

   不管哪一種，push 前都跑 `git status --ignored jobs/` 或 `git show --stat HEAD` 確認檔案真的在 commit 裡。
2. **label 框應該由貼回那一步直接記下來**，不要事後再從 `後−前` 推。貼回引擎知道自己貼在哪，輸出一個 `<鏡>_label.json` 給 B／C 用，可以少掉「模型原本畫得很像 → 差異太小」這種誤判。三支工具都已經留了 `--product-box`／`--fallback-box` 可以直接吃。
3. **擋門排進固定順序**：每鏡貼回後跑 B → 成片跑 A（`--box` 用商品區）→ 整包跑 C 出一張重驗圖給王看。任何一道 FAIL 就不進下一步。
4. **D 要從拍照開始配合**：透視對不上的根本解法，是真品照要有幾個角度（正面、左 3/4、右 3/4），由合成挑跟模型盒子同朝向的那張。另外模型盒子的位置最好在生成時就記下來，D 就不用再靠人給 `--box`。
5. **A 的門檻建議量「編碼前」的格或高畫質輸出**：壓縮雜訊會把比值往上推，越接近 0.25 的線越容易誤判。

