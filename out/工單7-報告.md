## 3. 哪些情況可能判錯（要本機用真圖看）
1. **白色／透明的部分碰到商品外緣**（白瓶蓋、白邊盒、透明窗＋白封邊）：會跟白背景連在一起被當成背景挖掉，商品變小、實心度變低。
   - 結果多半是要人眼或不收，**正例被誤判不收的最大來源**。
   - SOP 本來就要白色、透明商品先走 cutout-product.py；初篩只能盡量標「白色商品」。
2. **陰影、倒影**：灰色陰影跟背景差 > 24，會黏在商品上，商品框變大、實心度變低。
   - 框變大可能讓 700 以下的商品被量成 700 以上，這種會錯放。
3. **標籤瓶、雙色包裝**：「第二面」特徵會一直觸發，所以這類多半判要人眼，不是收。
   - 不會判不收：斜角不收要三個條件都有，對稱的瓶子進不了不收。
   - 代價是要人眼的比例偏高，等接了視覺模型、或本機用真圖調 `FACE_DIFF`／`FACE_SPAN`。
4. **從正上方往下拍的盒子**（看得到盒頂，但左右對稱）：只會判要人眼，不會不收。
5. **浮水印只蓋在商品上、背景沒有**：抓不到，因為浮水印是看背景的淡色塊。
6. **標章貼著商品**（間隔 0）：跟商品連成一塊，分不出來，當成商品的一部分。
7. **重複圖樣**：包裝本身有規律花紋（格紋、條紋）會誤判要人眼。多包疊放疊得很亂（不是整齊平移）會漏抓。
8. **背景是漸層或情境照**：外圈不到 60% 同色就只判要人眼；漸層剛好過 60% 的，商品框可能不準。
9. **長邊、高都是「商品框」量的**：斜放的商品框會比商品本身大。

## 4. 視覺模型介面怎麼接（給本機照做）
- **介面**：`Judge.ask(image_path, product_box, questions) -> dict`。
  - `questions` 固定四題：`single_product`（是不是單一商品）、`front_view`（是不是正面平視）、`added_text`（有沒有後加的字條、標章、浮水印）、`multi_pack`（是不是多包合成）。
  - 預設是 `NullJudge`，回 `{"status": "not_connected"}`。
- **HTTP 版** `HttpJudge`：打 OpenAI 相容的 `/v1/chat/completions`。
  - 圖縮到長邊 1024，用 JPEG 包成 base64 data URL，放在 `image_url`。
  - 提示詞要模型只回 JSON，值是 true／false，可以加 `note`。不確定就照比較嚴的答。
- **接的步驟**：
  1. 本機起一個支援看圖的 OpenAI 相容伺服器（例：llama.cpp 的 server 掛視覺模型＋mmproj，聽 127.0.0.1:8080）。用哪個模型、權重怎麼來，本機決定；這張單 ⛔ 下載。
  2. 先用一張圖試：`python tools/photo-screen.py 某張.jpg --judge http --judge-url http://127.0.0.1:8080 --judge-model <伺服器上的模型名> --json t.json`。
  3. 看 `t.json` 的 `judge.status` 是不是 `ok`、`judge.answers` 四題有沒有都回。網址只給到 port 就好，程式會補 `/v1/chat/completions`。
  4. 伺服器掛了、逾時、回的不是 JSON：`judge.status` 會是 `error`。初篩照跑，交給模型的題目一律要人眼，不會因為模型掛了就放行。
- **模型只能從嚴**（照工單）：
  - 程式判不收的不問模型（`judge.status = skipped`）。
  - 模型答「不是單一、不是正面、有後加字條、是多包」⇒ 收改成要人眼。
  - 交給模型的題目（正面判不準、商品裡的字條）**模型說沒問題也還是要人眼**，答案記在 `judge` 給人參考，因為工單說模型 ⛔ 讓結果變鬆。
  - 如果本機之後要讓模型替這兩題放行，那是政策改變，要改 `apply_judge` 一處；請先在 README 寫清楚再改。
- **測試**：`tests/test_photo_screen.py` 的 `FakeModel` 是程式內的假伺服器，可以照著它的回應格式對本機伺服器。
